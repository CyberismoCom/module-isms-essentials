== About the Cyberismo ISMS essentials module

The Cyberismo ISMS essentials module contains the basic building blocks for establishing an information security management system.
This includes example processes for

* asset management

* risk management

* incident management

along with the needed field types, link types, templates, workflows, registers, policy checks and progress metrics.

For a tutorial on how to get started with the Cyberismo ISMS essentials module, see the https://docs.cyberismo.com/cards/docs_y9v6f19e.html[ISMS essentials tutorial in Cyberismo documentation].

== The ISMS home

The template "ISMS home (core)" (`ismsa/templates/moduleHome2`) creates a home for the security work that a central team does once for the whole organisation. The core of the home has no controls. It has four registers:

* the central control register, for the internal controls of the home
* the process register, for the processes, policies, and plans of the home
* the incident register, for the incidents and near misses
* the compliance register.

The libraries add the controls, registers, and processes. So the first step in a new home is to choose its libraries. A team under an existing ISMS that already does the central controls leaves out the libraries that it does not need.

The home keeps one rule: all controls are in the central control register, the processes, policies, and plans are in the process register, and the other registers hold the records of the work. The process register has the same identifier as in the old home template (`ismsa_register_processes`).

Each control has planned evidence. The button in the control creates the evidence in the register that owns its topic, by default the process register. The evidence is linked to its control by identifier, only inside the same home. The assessment of a control is calculated from its evidence. When the EU CRA module is installed, the controls also show guidance for the Cyber Resilience Act.

The asset and risk management controls also check their registers. They are not OK while the register is empty, while an asset is not evaluated, or while a risk is not analysed or has no treatment plan. These checks replace the set-up tasks of the old home template.

The home card shows a "Getting started" checklist (`ismsa/reports/gettingStarted`). It lists the set-up steps of the libraries that have been added, in the order of the old set-up tasks, and ticks each step when its control is OK or out of scope. Before any library is added, it asks the user to choose the libraries first.

This module has five libraries:

[cols="2,3,4"]
|===
| Library | Installed in | Content

| Security response and compliance basics
| The central control register and the process register
| Six central controls: assign the central security roles, receive notifications of security issues, notify about vulnerabilities and incidents, contact with authorities, protect records, and follow changes in regulation. The incident management process

| Information security management
| The central control register and the home card
| Controls for the scope and context, the information security policy, training and awareness, and the planning and review of the ISMS. Registers for the security targets, the security reviews, and the tasks

| Asset and risk management
| The central control register, the home card, and the process register
| Controls for asset management and risk management. The asset register and the risk register. The asset management process and the risk management process

| Security operations
| The central control register
| Controls for security monitoring, incident response exercises, business continuity and recovery, and access rights reviews

| NIS2
| The compliance register
| The requirements of NIS2 Articles 20, 21, and 23 as assessed compliance requirements. The planned controls of the home are linked to them automatically
|===

A library has a template for each of its parts: its controls go to the central control register, its registers to the home card, and its processes to the process register. The section "Libraries" of the home card shows a button for each part, grouped by library, and ticks the parts that have been added. The section is open until the first part is added, and then it is closed to one line. The whole section is the report `ismsa/reports/homeLibrarySection`, and the buttons are the report `ismsa/reports/installLibraries`. So a new version of the module changes the section also in existing homes. A future version of Cyberismo can create cards in several places with one button, and then each library needs only one button.

A module registers a library with an `ismsa_installableExtension` fact. The extension points are listed in `ismsa/calculations/extensions`. The facts of the libraries of this module are in `ismsa/calculations/homeLibraries`.

The older template "ISMS home" (`ismsa/templates/moduleHome`) is still available, and existing homes continue to work.

== Tests

The test content is in `cardRoot`, under the page "Test content". To run the executable assertions of the central controls, run these commands in the root of this repository:

----
cyberismo calc run tests/central-controls.lp
cyberismo calc run tests/cra-guidance.lp
cyberismo calc run tests/home-libraries.lp
----

The tests pass when `results` is empty and `error` is `null`. The page "Central control assessment tests" shows the assertions of the central controls in the app. The page "ISMS home library tests" describes the fixtures of the libraries.
